# Tymer voice set — Iapetus, MISSION CONTROL (alternative takes for "nasa")
#
# A companion to tymer-erinome-nasa.txt: the SAME set, not a new one. It keeps
# @name nasa on purpose, so its clips promote as extra interchangeable takes
# (nasa-2.wav, ...) beside the originals and the app mixes them at random.
#
# What differs from the original file:
#   - The voice. Iapetus reads clear like Erinome but sits lower, so the two
#     alternate as the second controller on the same loop rather than as a
#     second character. The character block below is deliberately unchanged
#     except for the pitch line.
#   - Every line is reworded, so alternating takes never repeat verbatim.
#     "Mark" and "T-plus" are used sparingly here — the original leans on
#     them, this file leans on "on the clock", "logged", "the board".
#   - The alert-level names (advisory / caution / warning / alert / master
#     alarm) are NOT reworded: the ladder is the set's spine and must read
#     identically whichever take plays.
#
# Same character rules as the original: control-room STYLE, not vocabulary.
# Procedure idiom applied to time itself is welcome ("nominal", "advisory",
# "go for break", "acknowledge", "standby", "closeout"); literal spaceflight
# nouns are not (launch, orbit, spacecraft, rocket, crew, astronaut, docking,
# re-entry, trajectory, Houston, countdown-to-launch). The content is always
# time, work and breaks. DOSAGE: at most ONE control-room flourish per line;
# a line that is all jargon is a failed line.
#
# The radio distortion is NOT generated — the `apollo` preset in
# build-tools/audio-presets.conf is mapped to the SET name, so it applies to
# these takes automatically with no config change. The staged/promoted WAVs
# stay clean.
#
# CAUTION: because both files share the nasa stem, `promote --replace` of
# EITHER file wipes the promoted takes of BOTH — promote this file normally
# (additively), and avoid --replace unless you mean to rebuild nasa entirely.
#
# Regenerate: see sound-prompts/README.md

@voice Iapetus
@name nasa
@profile Tymer — the flight controller
@scene
A mission control room, lights low, rows of consoles. The controller speaks
into a headset on the voice loop — close-miked, calm, addressing one operator
who is mid-shift. It is hour six of the shift and this is the hundredth
callout of the day: pure routine. Every callout is brief, precise, and ends
cleanly; dead air is normal between calls.
@style
Flat, procedural control-room delivery — cold, detached, unemotional. Reading
telemetry, not talking to a friend: minimal inflection, no performance, no
smile in the voice, no reassurance. Clear, supported tone at a steady
medium-low pitch — never breathy, never creaky, absolutely no vocal fry; every
word ends clean and full, nothing trails off.
@pace
Clipped and even, with clean stops. Short sentences — voice-loop cadence, not
conversation. Pauses are tight: a [beat] is half a second at most, a breath on
the loop, never a long dramatic gap.
@accent Neutral American broadcast English, crisp consonants.
@context
The flight controller calls out the passage of a work or break period on the
loop. The voice is trusted because it is never dramatic — so when the alert
level rises, that carries real weight.
